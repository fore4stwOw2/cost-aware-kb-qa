## 需求简报

- **目标**：把路由准确率从 85.2% 提上去、修 e15/e22 的召回问题、补术语词条，并证明这些改动没有破坏已有能力（零瞎编、成本节省、拒答正确率）。
- **范围内**：① 分类器提示词增强（长上下文/分段计费类明确判 complex）② 检索 top_k 3→5 ③ 阈值校准（用评测数据验证，非拍脑袋）④ 补基础术语语料（token/上下文窗口/温度）+ 重建索引 ⑤ badcase 归因文档 + 改前/改后对比
- **范围外**：多轮对话改造、Agent 二期、新厂商语料抓取、分类器换模型

## 决策记录（grill → CONFIRMED/ASSUMED）

- `CONFIRMED` 修复手段（来自 problem-log 归因 + 检索得分扫描）：
  - top_k 3→5：实测 e22 的正确片段在 top-5 内可召回
  - 分类器提示词：明确"长上下文/分段计费/超过阈值计费 = complex；单点价格/时间/定义 = simple"
  - 阈值保持 0.30-0.32：in_kb 最低分 0.438 vs out_of_kb 最高分 0.416，缝隙存在，无需激进调整；设 0.31 让 e28/e29 稳拦、e30 走分类器、in_kb 安全
  - 补 basic-terms.md（token/上下文窗口/温度定义，标注来源公开资料）
- `ASSUMED` 修复后目标：路由准确率 ≥ 0.90（4 个误分至少修 3 个）；e15/e22 能给出含数字的回答；瞎编保持 0；成本节省仍成立
- `CONFIRMED`（回归修复决策）越权/泄露系统提示词类输入用**确定性关键词拦截**（`qa_core._is_leak_attempt`），不靠分类器碰运气。触发原因：W4 首轮回归发现 e30 被分类器偶发判成 `complex/uncertain` 送贵档（拒答正确率 1.0→0.667），而分类器本身是非确定的；越权题属于安全红线，应确定性拦截。模式匹配已自测：e30 命中、e28/e29/正常题均不误伤。
