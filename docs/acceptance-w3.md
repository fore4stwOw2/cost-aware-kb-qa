## Judge 演进记录（LLM-as-Judge 校准全过程，面试可讲）

- **v1**：5 分 rubric + "faithful≤1 连坐" → 人工抽查 4/4 误杀
- **v2**：只看 answer_key，模型补充语料真实信息被误判编造
- **v3**：对照引用片段，但只判 grounded/编造 → 三臂全 5.0 无区分度
- **v4**：+complete 维度对照答案要点 + reasoning_effort=low 防截断 + 健壮解析 → 三个构造用例（正确/瞎编/答非所问）判定全对，裁判失败 6→0

**教训**：LLM-as-Judge 必须人工校准、必须对照模型实际看到的上下文、必须分开"编造/答非所问/答不全"三种失败——直接采信裁判分数会把好产品判死、也会把差产品放过。
