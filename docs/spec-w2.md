# W2 需求简报 + 验收标准（留痕）

> ai-native-dev-flow 第 1、2 步产物。第 3 步三角色执行见 git 历史与 `docs/acceptance-w2.md`。

## 需求简报

- **目标**：给知识库问答装上"路由大脑"——先判断难度和可答性，简单问题走便宜档、复杂问题走贵档、库外直接拒答，在守住回答质量的前提下降低平均调用成本；上游故障自动降级。
- **范围内**：① 分类器（便宜模型做结构化三维分类）② 双档路由 + 成本/理由展示 ③ 可答性拒答（阈值退化为兜底）④ 故障降级链（重试一次 + 跨档顶上）⑤ ask.py 支持 `--mode flash/pro/route`（W3 评测地基）
- **范围外**：正式跑分与三臂对比（W3）、badcase 修复回归（W4）、第二家服务商真降级（二期）、UI 大改版
- **假设/确认**：
  - `CONFIRMED` 贵档 = deepseek-v4-pro（用户确认；与 flash 同 key、价差 3 倍）
  - `ASSUMED` 分类器输出三维标签：难度（简单/复杂）+ 可答性（库内/库外/不确定）+ 一句话理由；"不确定"按复杂处理送贵档
  - `ASSUMED` 界面显示路由理由（透明度优先）
  - `ASSUMED` 降级链 = 重试一次 + 跨档顶上并标注"降级运行"；"同厂同时挂"的局限在 README 如实写明
  - `ASSUMED` 阈值 0.30 保留为第二道兜底，正式调优放 W4

## 验收标准

| # | 标准（独立可判定） |
|---|------|
| AC1 | 问"token 单价怎么算"（简单题）由 flash 回答；问"对比 DeepSeek 和 Claude 的定价并给选型建议"（综合题）由 v4-pro 回答；两条均显示所用模型、路由理由、成本 |
| AC2 | 问"鸡吃什么"被分类为库外 → 直接拒答、$0、界面显示理由；阈值兜底仍有效（`--threshold 0.99` 时所有问题都走拒答） |
| AC3 | 对分类器拿不准的问题，若判"不确定"则送贵档回答且不瞎编 |
| AC4 | 主档模型失败（用 `CHEAP_MODEL=不存在的模型` 模拟）→ 自动重试 → 仍失败则换另一档顶上并显示"降级运行"标注；base_url 全错时给出清晰错误信息、不崩溃 |
| AC5 | ask.py 支持 `--mode flash/pro/route` 三种模式，同一批问题可分别运行并输出各自总成本 |
| AC6 | 回归：W1 的 9 题在路由模式下重跑，0 例瞎编，原答对的定价题仍答对 |
