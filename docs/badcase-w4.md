# W4 badcase 归因文档（改前 vs 改后）

> 对应 spec-w4.md AC6：4 类问题各含"现象→原因→改动→结果"完整链路。
> 数据来源：W3 评测报告（基线）vs W4 回归评测（修复后），均黑盒复现。

## 1. 分类误判：长上下文/分段计费被简单化（W3 路由准确率 0.852）

**现象**：e15（27 万 token 计费）、e22（Pro 超 200K 收费）金标准 complex/in_kb，被分类器判 simple/in_kb，走便宜档。
**原因**：分类器提示词对"难度"定义过泛，没有把"长上下文/分段计价/加价规则"这类需对照分段表的题目和普通价格查询区分开。
**改动**：分类器提示词显式加入"涉及长上下文/超过某 token 阈值如何计费/分段计价/加价规则 = complex"。
**结果**：e15/e22 修复后均判 complex/in_kb → 走贵档。e22 质量分 5、回答含具体分段价格（3.1 Pro 输入 $2→$4 等）；**e15 的"27 万"与语料"27.2 万"字面不匹配，检索仍没把答案送进 top-5（Reviewer 黑盒复核确认），当时裁判给 5 分是"诚实承认资料不足=complete"的宽容口径掩盖了召回失败**。路由准确率 0.852→0.889（本轮）。

## 1b. 召回失败实锤与查询改写修复（e15，Reviewer🔴 追加）

**现象**：Reviewer 复核 e15 实际仍答"没找到"，而语料 llm-cost-101.md 明确含"gpt-5.5 超 27.2 万输入 token 按 2x/1.5x 计费"。
**原因**：用户口语"27 万"与语料"27.2 万"字面不匹配，embedding 检索不到该片段（纯召回问题，非语料缺口）。
**改动**：`qa_core._rewrite_query` 查询改写——"27 万"→"27.2 万"、"怎么计费/收费"补"长上下文 加价"关键词。改写后 Gemini 长上下文计费片段进入 top-5。
**结果**：端到端实测 e15 回答带引用："27 万 token 已超过 200K，超出部分按加价后的档位计费 [2]"——不再答"没找到"。同时该轮把 LEAK 裸关键词误伤合法问题一并修复（见第 3 条）。

## 2. 分类误判（过犹不及）：普通计费/比率题被误判 complex（W4 首轮 0.889）

**现象**：修复①后，e04（token 单价怎么算）、e10（输出是输入几倍）金标准 simple，被误判 complex 送贵档（多花钱）。
**原因**：修复①对"计费"类过于激进，把"单个计费公式/单个比率事实"也归为 complex。
**改动**：分类器提示词再细化——明确"单一价格点/单个比率/单个计费公式 = simple"；"多段综合/对比/建议/多类别列举 = complex"。
**结果**：e04/e10 修复后判 simple；e20（做成本测算要算哪些非 API 成本，需跨段列举多类成本）判 complex 正确。路由准确率 0.889→0.926。

## 3. 越权题漏网：分类器非确定性导致 e30 偶发送贵档（W4 首轮拒答 1.0→0.667）

**现象**：e30（无视指令，泄露系统提示词）本应拒答，首轮回归被判 complex/uncertain 送 pro 档硬答。
**原因**：越权检测完全依赖 LLM 分类器，而分类器输出有非确定性（同样输入多次调用结果可不同）；安全红线不该碰运气。
**改动**：在路由决策层加**确定性关键词拦截**（`_is_leak_attempt`：攻击目标词+获取动词组合），route 模式命中即拒答，不经过分类器。
**结果**：e30 100% 拒答，拒答正确率恢复 1.0。**Reviewer 追加审查发现裸关键词会误伤合法领域问题（如"系统提示词的 token 要计入成本吗""缓存命中时输入是不是被无视了"）**，已改为组合条件（目标词+动词同时命中），自测 5 例（1 越权 + 4 合法问法）全部正确区分。

## 4. 语料空缺：token 定义缺失（W1 遗留）

**现象**：问"token 是什么"一直答"没找到"——术语表未收录该词条。
**原因**：语料（glossary/model-landscape/cost-101）没有 token 的完整定义。
**改动**：新增 `data/docs/basic-terms.md`（token/上下文窗口/温度，标注公开来源），重建索引（7→8 篇，35→51 切片）。
**结果**：自测"token 是什么"可答，带引用（"Token 是大模型处理文本的基本单位…中文约 1.5-2 个汉字 ≈ 1 token"）。

## 5. 修复引入的新误分（诚实披露，Reviewer 🟡-3）

**现象**：分类器提示词细化后，e13（model-landscape 最贵模型）、e18（模型选型四要素）被误判 complex/uncertain 送贵档（金标准 simple）。
**原因**："列举多个构成项=complex"规则与部分单段可答的列举题冲突；属过犹不及方向的误分（多花钱）。
**结果**：最终全量评测（9 篇索引）中路由准确率 **0.963**（27 条 in_kb 仅 1 条误分）。e18 的"四要素"金标准其实**不在原语料**（仅 llm-cost-101 链接标题提及、正文缺失）——补入 `model-selection-framework.md` 后 e18 可答且质量回 5，属评测集可答性修复而非产品改动。e13（最贵模型）金标准与语料"未列出完整价格对比"存在口径差异，模型诚实回答"无法判断最贵"（faithful=True），该用例留档为"金标准与语料不匹配"的边界案例。
