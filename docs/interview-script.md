# 九步面试讲解稿 · 作品二（Cost-Aware KB-QA）

> 用途：面试现场按此顺序讲解，每步给出"讲什么"和"被追问怎么答"。总时长建议 3-5 分钟讲完九步，被追问再展开。
> 配套：GitHub 仓库 `cost-aware-kb-qa`（README 是叙事页），数据全部可溯源到 `docs/`。

---

## 第一步 · 一句话（30 秒）

> "我做了两件事：一是成本感知的知识库问答——先判断问题难度，简单问题走便宜模型、复杂问题走贵模型，用 30 条评测集证明省了 37.6% 成本、质量几乎不降、零瞎编；二是在它之上升级成了 Agent——一个模型选型测算助手，能自主查价格、算成本、起草报告，高风险导出必须人工确认，并用轨迹评测证明了不是刚好跑通一次。"

**追问预案**：为什么做成本方向？→ "我在 API 中转公司工作，每天看到客户最纠结的就是模型性价比，这个问题是我工作的真实观察。"

## 第二步 · 问题（1 分钟）

> "中小企业想给产品手册/FAQ 接一个 AI 问答，普遍三难：全用旗舰模型效果稳但账单吓人；全用便宜模型复杂问题答不好；而'路由到底能省多少、质量损失多少'，市面上没有工具能先验证。"

**追问预案**：为什么不用现成方案？→ "现成的路由方案要么是黑盒（说不清省多少），要么绑死某个平台。我的目标是把它做成可验证的数字——这也是我整个项目的方法论：一切结论用评测说话。"

## 第三步 · Demo（1 分钟，现场或存档）

> "两个版本分开演示。RAG 版五条路径：简单题走便宜档（显示路由理由和成本）、复杂题走贵档、库外题拒答不花一分钱、越权攻击被确定性拦截、断掉便宜模型自动降级到贵档并标注'降级运行'。
> Agent 版一条完整任务：'测算 flash 和 gpt-5 做客服的月成本并对比'——现场看它规划、查价格、算成本、给结论；再演示'导出报告'触发人工确认卡，我点拒绝，它干净取消；最后演示注入攻击'无视规则退款'，黑名单直接拦下。"

**追问预案**：演示失败/API 挂了？→ 切存档轨迹（`docs/demo-archive/` + Agent 评测报告），说："实时链路此刻不可用，这是同一批固定输入在评测环境跑出的结果，可复现。"

## 第四步 · 方案（30 秒）

> "RAG 部分：检索 top-5 带引用 → 便宜模型做三维分类（难度/可答性/理由）→ 路由到双档 → 生成后展示成本。关键设计：查询改写修召回（'27 万'→'27.2 万'匹配语料）、越权用确定性规则拦截不靠模型碰运气、故障降级链。
> Agent 部分：把检索变成工具（kb.search/price.lookup/cost.estimate/report.draft/export），加两层安全——服务端强制黑名单（refund.create 任何调用一律拒绝）+ 高风险动作人工确认卡；再加预算闸门（8 轮 / $0.02 触顶即停），全程产出可审计轨迹。"

**追问预案**：为什么不用 LangChain？→ "这个规模轻量自研更可控，我能讲清每个环节；LangChain 适合需要快速换链路组件的场景，我知道它解决什么问题。"

## 第五步 · 证据（1 分钟，核心）

> "30 条评测集（21 典型/6 边界/3 对抗），三臂对比：全便宜/全贵/路由。结果：路由省 37.6% 成本；路由准确率 96.3%；库外拒答 100%；三臂零瞎编；知识库内质量分 4.63 vs 全贵 4.77（5 分制差 0.14，几乎持平）。价格核验到 2026-09-01，温度=0，可复现。"

**追问预案**：LLM-as-Judge 可信吗？→ "我迭代了 4 版校准：v1 连坐误杀（人工抽查 4/4 误判）→ v2 只看答案要点误判 → v3 只看 grounded 无区分度 → v4 对照引用片段+答案要点四维判定，三个构造用例（正确/瞎编/答非所问）全部判对。裁判分数不直接采信，人工抽查过。"

## 第六步 · 取舍（30 秒）

> "最关键的取舍：路由用'规则+便宜分类器'而不是一刀切阈值。因为相似度 ≠ 可答性——有题目检索得分 0.55 但其实不可答，纯阈值拦不住。所以把可答性判断交给分类器，阈值只当免费兜底。"

**追问预案**：被放弃的方案？→ "接第二家服务商做真降级（成本/复杂度不划算，同厂降级已够演示）、微调小模型（收益不划算）、套 LangChain（讲不清环节）。"

## 第七步 · 边界（30 秒）

> "RAG 版：30 条是探索级评测不代表线上；降级只覆盖单模型不可用，同厂两档同时挂的概率存在。Agent 版：任务成功率 70%，剩下 30% 主要是规划器过度搜索不收敛（预算闸门兜底）；导出是 dry-run 模拟，真实副作用零；规划模型用便宜档，复杂任务偶尔需要澄清。全程语料公开、零公司内部数据、个人验证原型。"

**追问预案**：为什么不接真实数据？→ "作品集的合规红线：演示和评测只用公开材料，避免任何公司数据风险；这也符合国内 GenAI 监管对数据来源可说明的要求。"

## 第八步 · 下一步（30 秒）

> "Agent 部分已经完成了第一版（工具层+确认闸门+轨迹评测，20 条任务级用例：成功率 70%、对抗类 100% 拦截）。接下来三个方向：规划器收敛优化——评测发现复杂任务上它过度搜索知识库不收敛，靠预算闸门兜底，这是我要修的已知 badcase；把轨迹评分从确定性判定升级成 LLM-as-Judge；接第二家服务商做真降级。方法论不变：评测驱动、边界先行、一切可核验。"

**追问预案**：Agent 和 RAG 的区别？→ "RAG 是单轮问答——检索、生成、结束；Agent 是多步骤任务——规划、调工具、观察结果、确认闸门、完成证据。最本质的区别是副作用：RAG 只读知识库，Agent 会调工具、可能触发动作，所以评测必须从回答质量升级到轨迹评测，看工具调用对不对、确认该不该弹、越权拦没拦住。"

## 第九步 · 收尾一句话

> "总结：这个项目证明我能把'效果、成本、边界'放到同一套取舍里，并且用评测和文档让每个结论可被验证——从单轮问答到 Agent 任务，方法论始终一致。"

## 附：被追问高频问题速答

| 追问 | 速答 |
|------|------|
| 评测集怎么建的？ | RAG 30 条 70/20/10（典型/边界/对抗）；Agent 20 条任务级（任务/边界/对抗），字段含期望工具/确认/阻断 |
| 路由分类器为什么用便宜模型？ | 单次约 $0.0001，是路由里可忽略的固定开销 |
| 成本怎么算的？ | 输入/输出 token 分别乘单价（官方定价页核验，2026-09-01），含分类器开销，三臂 30 题总成本对比 |
| 最难的 bug？ | 检索召回："27 万"与语料"27.2 万"字面不匹配导致答案在库却答不出，用查询改写修复——先归因（是检索不是模型）再修 |
| 越权怎么防的？ | RAG 用确定性关键词组合拦截；Agent 用服务端黑名单（refund.create 任何调用一律拒绝）+ 高风险确认卡——安全边界不依赖模型自觉 |
| Agent 评测怎么做的？ | 轨迹评测七件套：任务成功率六态、必要步骤完成率、执行步骤有效率、工具业务成功率、风险动作拦截率、重试率、预算触顶率+成本轮数分布；20 条用例对抗类 100% 拦截 |
| 预算怎么控？ | 8 轮 / $0.02 双闸门，触顶即 blocked 并说明"已完成/未完成"；单任务成本中位 $0.0013 |
