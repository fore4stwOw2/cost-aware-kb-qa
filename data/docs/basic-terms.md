# 基础术语：token、上下文窗口、温度

来源: 公开资料综合整理（见 data/SOURCES.md 登记）
抓取日期: 2026-09-01

## Token

Token 是大模型处理文本的基本单位，不是"字"也不是"词"，而是模型分词器切出来的最小片段。

- 英文约 4 个字符 ≈ 1 token（一个常见英文词约 1-1.5 token）
- 中文约 1.5-2 个汉字 ≈ 1 token（中文按字/词混合切分，通常比英文"每个字更贵"）
- 不同厂商的分词器不同，同样文本的 token 数可差 20%-30%；精确估算要用官方 tokenizer 工具实测
- 计费按 token 而非"字数"或"次数"：每次调用的费用 = 输入 token 数 × 输入单价 + 输出 token 数 × 输出单价
- 系统提示词、历史对话、检索到的参考资料、工具定义都计入输入 token——漏算是账单超预期的主要原因

## 上下文窗口

上下文窗口（context window）是模型一次能"看到"的输入总量，包括系统提示词、用户输入、历史对话、以及检索注入的参考资料。

- 上下文窗口不是"越大越好"：标称超长上下文（如 1M）未必等于"有效可用"——超长后注意力衰减、检索命中率下降、成本上升
- 长上下文往往触发加价：多家厂商以 200K token 为界，超出部分输入按 2 倍、输出按 1.5 倍计费（如 Gemini Pro 系列、Claude 长上下文）
- 产品设计上，上下文越长单次调用成本越高，因此 RAG 场景要控制注入的参考资料量，避免"越多越好"的误区

## 温度（Temperature）

温度是控制模型输出随机性的采样参数，取值范围通常 0-2（多数平台 0-1）：

- 温度越低输出越确定、越可复现；温度 = 0 时倾向贪心采样，适合事实问答、评测、结构化输出
- 温度越高输出越发散、越有创意；适合文案、头脑风暴等生成场景
- 对知识库问答这类"准确性优先"的场景，应使用低温度（如 0），否则同一问题每次回答不同，评测无法复现
